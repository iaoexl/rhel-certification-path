## README · 专项知识库导览

主知识库按能力递进组织二十三个板块，讲的是"通用主干"：一套在主流企业级发行版上走通的系统管理与服务部署方法。但真实机房里的问题不总是长在主干上——一台装着 Ubuntu 的开发机、一套 Zabbix 监控、一批迈普与 H3C 交换机、一台只能从 Windows 侧操作的数据库服务器，都属于"偏离主干但必须会"的部分。把它们硬塞进主干板块，会破坏主线的逻辑；丢掉又会让知识库在关键时刻接不住问题。这个专项库就是这些内容的归处。

每个专项都可独立阅读、独立验证，不要求先读完主干对应板块；但它们默认读者已经具备主库前六个板块的基础（命令行、权限、服务管理、防火墙），文中不再重复讲解这些通用操作。

### README_1 定位与分工原则

判断一段内容该进主干还是进专项，只有一条标准：**它是否属于所有 Linux 管理者都必须掌握的主干能力**。属于，进板块；只在特定环境、特定产品、特定设备上才用得上，进专项。

| 判断维度 | 归入主干板块 | 归入专项库 |
| --- | --- | --- |
| 发行版 | 红帽系通用做法 | 某一发行版的独有机制（如 Ubuntu 的 Netplan） |
| 产品 | 系统自带组件 | 第三方产品（如 Zabbix） |
| 设备 | 服务器本机 | 网络设备、Windows 主机 |
| 生命周期 | 长期有效的方法论 | 特定版本才成立的兼容性调整 |

按这条标准划分后，主干讲"为什么这样设计"，专项讲"这个环境里具体怎么做"。两者共享同一套写作约定与验证方法，笔记可以放在同一个仓库里按目录区分。

### README_2 专项索引

| 编号 | 专项名称 | 覆盖内容 | 典型使用场景 |
| --- | --- | --- | --- |
| 专项1 | Ubuntu 系统管理 | Netplan 声明式网络配置、rc.local 在 systemd 下的复活与替代、apt 与 dpkg 的包管理、ufw 与 firewalld 的对照 | 接手 Ubuntu 服务器或开发机，发现改 `/etc/network/interfaces` 无效，或习惯红帽系命令后装包与放行总是差一步 |
| 专项2 | Zabbix 监控体系 | 三层架构、两种检查方向、SELinux 与 PHP 扩展前置、数据库调优、服务端缓存参数、采集端接入、指标设计 | 从零搭一套主机监控；排查"前端一片空白"或"数据量上来后开始丢数据" |
| 专项3 | Windows 主机运维 | 账户与登录、磁盘与启动修复、服务与任务、诊断工具 | 机房里有 Windows 服务器需要一并维护 |
| 专项4 | 网络设备配置 | 视图层级、端口安全、远程登录认证、NAT Hairpin | 需要登录交换机改配置、绑定 MAC、开通内网回访 |
| 专项5 | Windows 平台数据库运维 | MySQL 逻辑备份与自动化、库改名迁移、SQL Server 部署与远程访问 | 数据库跑在 Windows 上，或用 Windows 侧脚本做备份 |
| 专项6 | 硬件监测与定时开关机 | 温度与风扇读数、BIOS 定时开机、定时关机与电源状态 | 排查过热降频、做定时开关机的节能或值守方案 |
| 专项7 | CentOS 7 系统初始化与兼容性调整 | 网卡命名回退、默认启动目标、启动链路与 SysV 服务管理、装机后初始化清单、DNS 落点 | 老系统改造、批量初始化、脚本因网卡名变化而失效、判断开机卡在哪一环 |

选读顺序建议按"遇到的概率"排：专项7 与专项1 是装机后立刻会碰到的兼容性问题，专项2 是运维岗最常见的建设任务，专项4 与专项3 取决于所在环境是否包含网络设备与 Windows，专项5 与专项6 属于按需查阅。

### README_3 结构与阅读约定

每个专项文件采用统一结构，与主库的板块范式保持同构，便于交叉检索。

| 段落 | 作用 |
| --- | --- |
| 板块0 · 学习路径和建议 | 给出阶段目标与验证方式，并声明适用范围与边界 |
| 板块1 起 · 各主题板块 | 按"原理 → 概念 → 实操 → 验证"推进，每个板块内部再分子板块 |
| 末尾板块 · 要点回顾与能力自检 | 浓缩结论，给出五到七道自测问题 |

写作约定与主库一致：命令提示符统一用 `root@iaoexl:~#`（网络设备用 `Switch>`、`[H3C]` 等设备自身提示符，Windows 用 `C:\>`），内网示例地址统一取 `192.168.10.0/24`，机制说明用纯文本 ASCII 图，配置与输出用等宽代码块。示例中的账号统一为 `iaoexl`（系统账号与服务账号除外），口令统一为 `iaoexl@7#13`，只用于隔离的实验环境。

### README_4 使用建议与边界声明

专项内容有明确的版本语境，脱离语境照搬会出问题，这一点必须先说清。

| 专项 | 版本语境 | 需要注意的变化 |
| --- | --- | --- |
| 专项1 | Ubuntu 24.04 LTS（Netplan 1.x） | `gateway4` 自 20.04 起弃用，现统一写 `routes`；`renderer` 默认值随桌面版与服务器版不同 |
| 专项2 | Zabbix 7.0 LTS 为部署基准，3.x~6.x 的差异列表对照 | 7.0 要求 PHP 8.0 与 MariaDB 10.5 以上；`innodb_status_file`、`innodb_support_xa`、`query_cache_size` 等旧参数已移除，照抄旧 `my.cnf` 会让数据库起不来 |
| 专项3 | Windows 7、Windows 10 与 Server 2016 及以上 | 新版把部分入口从控制面板迁到"设置"；`EnablePeriodicBackup` 默认关闭导致 `RegBack` 为空，涉及注册表的操作务必先备份 |
| 专项4 | 迈普与 H3C 中低端设备 | 命令语法在同厂商不同系列间存在差异，配置前用 `?` 补全确认，不要跨型号照抄 |
| 专项5 | MySQL 5.7 至 8.4、SQL Server 2016 及以上 | 8.0 默认字符集改为 utf8mb4、默认启用 `caching_sha2_password`，旧客户端需调整认证插件；SQL Server 新版安装向导选项有调整 |
| 专项6 | 通用 x86 服务器与主板 | 定时开机依赖主板 RTC 与电源管理支持，虚拟机与部分云主机不提供该能力 |
| 专项7 | CentOS 7 为主，启动流程与 SysV 部分下探到 CentOS 6 | 该系统已停止维护，仅作存量环境参考；GRUB Legacy 与 GRUB 2 的配置位置不同，`grub.conf` 与 `grub2/grub.cfg` 不要混用 |

三条使用边界：涉及磁盘、注册表、生产数据库的操作先在虚拟机或测试库验证；关闭防火墙、关闭 SELinux、明文传输口令这类"图省事"的做法只在隔离环境使用，不得带入生产；专项中的数值与路径来自特定实验环境，迁移到自己的环境时先核对设备名、目录与版本。

专项库与主库共用一套笔记方法：每条记录写清操作、输出与结论，注明适用版本与环境差异。版本语境是专项笔记里最该记的一项——同一个参数在不同版本上含义不同，写下来才不会在半年后重复踩坑。
